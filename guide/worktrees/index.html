    Worktrees and git¶

    Pre-run checks¶

    Before the first iteration, ralpher checks the repository that contains --cwd (or the current directory), and asks before carrying on:

    Check Prompt default
    Not in a git repository continue? no
    Working tree has changes, including untracked files continue? no
    The current branch has commits its upstream lacks (after git fetch origin) continue? no
    ralpher cannot tell whether there are unpushed commits (no origin, a failed fetch, a detached HEAD or no upstream) continue? no
    With --worktree and a fresh base: origin/HEAD is not the current branch exit now? yes

    The unpushed-commits check is skipped when worktrees are created from the local HEAD (below). When ralpher cannot tell whether there are unpushed commits, it says so and asks whether to continue; the default is no, and answering no exits.

    The prompts read from the terminal, so an unattended run that hits one waits. Commit and push first, or pass --skip-git-check to skip every check.

    --worktree¶

    With --worktree, ralpher adds --worktree <name> to the agent's arguments, and Claude Code runs the agent in a git worktree of that name, on the branch worktree-<name>. Every iteration passes the same name, so every iteration uses the same worktree. --args may not contain --worktree or -w: ralpher refuses it with an error, so every check and hook agrees with the agent on whether a worktree is used.

    The name comes from the tasks file's absolute path: its directory name and its stem, joined with -, lowercased, with every run of characters other than a-z and 0-9 turned into one -. Claude Code accepts worktree names of at most 64 characters, so a longer name is cut to at most 55 characters and ends with - and the first 8 hex digits of the full name's SHA-256; the branch is still worktree-<name>.

    --task-file Worktree Branch
    agents/tasks/config-loader/tasks-1.md config-loader-tasks-1 worktree-config-loader-tasks-1
    TASKS.md <repo-dir>-tasks worktree-<repo-dir>-tasks

    Without --task-file, --worktree is passed on its own and Claude Code picks the name.

    The prompt must tell the agent to work in the worktree; the bundled one-task prompt does when {{ worktree }} is true. See Prompts.

    Giving the worktree an environment¶

    The agent creates the worktree empty: it has no virtual environment and no installed hooks. A check that falls back to the tool on PATH then runs a different version from the one the project pins. Set worktree_setup in .ralpher/settings.json to a list of commands:

    {
  "worktree_setup": ["uv sync"]
}

    With --worktree, the bundled one-task.md prompt tells the agent to run each command in the worktree, in order, before anything else, and to report the task blocked if one fails, rather than borrow another checkout's environment. Every iteration's agent runs the commands, so each must be safe to repeat.

    Without the setting, ralpher prints a warning before the first iteration and carries on. See Settings.

    Where the worktree starts¶

    Claude Code's worktree.baseRef setting decides what a new worktree is created from:

    • fresh (Claude Code's default): origin's default branch. Unpushed commits and local changes are not in the worktree.
    • head: your local HEAD, without uncommitted changes.

    --worktree-base-ref fresh|head passes the setting to the agent as --settings '{"worktree": {"baseRef": "..."}}'. --args may not contain --settings: ralpher refuses it with an error. See the Claude Code settings reference.

    The pre-run checks use the same value the agent gets: --worktree-base-ref when ralpher passes it, otherwise worktree.baseRef from Claude Code's settings files (user, project, local and managed).

    Flags refused in --args¶

    --args holds Use instead
    --worktree or -w ralpher's --worktree
    --settings --worktree-base-ref, or ralpher's settings files

    ralpher stops before the first iteration with an Error: line naming the flag. The tasks file ralpher reads for the stop check and for hook prompts is the worktree copy only under --worktree.

    After the queue¶

    When a run ends complete, with no error or termination, and used --worktree and --task-file, ralpher prints the commands to fold the work back in:

    Probable cleanup commands...
  cd <repository root> && \
  git merge --no-ff --no-edit worktree-<name> && \
  (git worktree unlock <name> 2>/dev/null || true) && \
  git worktree remove --force <name> && \
  git branch -D worktree-<name> && \
  git push && \
  (git push origin --delete worktree-<name> 2>/dev/null || true)

    The cd line appears when --cwd is set, as rrq.sh sets it. They are printed, never run. Run them from your checkout of the branch the worktree started from. git branch -D is used rather than -d because a branch pushed for CI, then committed to, is refused by -d even once merged, and the chain would stop before the push.

    --cleanup prints the same commands without running anything, for a queue that finished earlier:

    ralpher.sh --cleanup --worktree --task-file agents/tasks/config-loader/tasks-1.md

    rcl.sh <spec> <n> is that call for a queue started with rrq.sh.
